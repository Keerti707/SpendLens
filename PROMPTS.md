# Prompts

## Where AI is Used

SpendLens uses AI only for the personalized executive summary shown in the audit report. The audit math itself is deterministic and rule-based.

This separation is intentional:

- financial calculations should be explainable and testable
- LLMs can hallucinate numbers or invent unsupported recommendations
- the AI layer is useful for summarizing the result in a more readable way

## Runtime Prompt Used in the App

The following prompt is used in `app/api/summary/route.ts`.

You are generating a concise executive summary for an AI spend audit.

Write around 100 words.
Be specific, practical, and finance-aware.
Do not exaggerate.
Do not invent exact facts beyond the provided audit data.

Audit data:
Total monthly spend: ${{totalMonthlySpend}}
Estimated monthly savings: ${{totalMonthlySavings}}
Estimated annual savings: ${{totalAnnualSavings}}
Number of tools audited: {{toolCount}}

Tool recommendations:
{{toolResults}}
Why This Prompt Is Written This Way

The prompt asks for a concise executive summary because the product is meant for founders, engineering managers, and finance-aware operators who need a fast answer.

I included instructions like “do not exaggerate” and “do not invent exact facts” because the summary should not overstate the audit. The product needs to feel trustworthy, especially because it talks about money.

The prompt includes only already-computed audit data. The model does not calculate savings. It only explains the result.

Fallback Behavior

If OPENAI_API_KEY is missing or the API request fails, the app falls back to a rule-based summary generated by the audit engine.

This means:

the app still works during local review
production does not break without API credits
the user still receives a useful summary
the audit math stays independent from the LLM
What I Tried That Did Not Work

I considered using AI to generate the savings recommendations directly, but rejected that approach because it made the audit harder to trust. For this product, the financial logic should be deterministic and defensible.

I also avoided asking the model to compare every AI tool from scratch because that could produce subjective or stale claims. Instead, I used rule-based pricing logic and let AI summarize the already-computed findings.

What I Would Improve Next

With more time, I would add:

separate prompts for low, medium, and high savings cases
a stricter JSON output schema
source-aware summaries tied to pricing data versions
prompt evaluation examples
regression tests for summary quality
